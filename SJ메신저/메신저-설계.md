## 1. 화면 — 카톡 대응표

| 카톡 | SJ 메신저 | 지금 코드 |
|---|---|---|
| 채팅 목록 | **채팅목록** — 방 이름 · 마지막 말 · 시각 · **안읽음 배지** | 있음 (`filterChannelsDOM` · `getUnreadCount`) |
| 채팅방 | **채팅방** — 좌우 말풍선 · 시각 · **읽음 '1'** · 사진 미리보기 · 하단 입력바 | 있음(데스크톱 기준) → **모바일 우선으로 재배치** |
| + 첨부 · 카메라 | 입력바 **📷 카메라 · + 사진/파일** | 파일 드롭만 있음 → **`<input capture>` 카메라 추가** |
| 1:1 · 단체 | DM · 단체방 · **봇 방(파이스)** | DM·단체 있음 (`startDM` `startGroup`) → 봇 방 추가 |
| 알림 | **푸시** — 잠긴 폰에 뜨고 누르면 그 방 | 없음 → FCM + 서비스워커 |
| 프로필·설정 | 플랫폼 것 재사용 | — |

**화면은 둘**(채팅목록·채팅방)이 전부다. 카톡이 그렇다. 확인 카드는 방 안의 **메시지 한 종류**(`type: 'card'`)라 새 화면이 아니다.

레이아웃: 지금 `@media (max-width: 850px)` 하나로 데스크톱→태블릿만 대응한다. **폰이 기본, 데스크톱이 예외**로 뒤집는다(iframe 안에서도 그대로 동작해야 한다 — `pFb` 부모 연동 유지).

## 2. 작동 방식 (m2)

```
직원   사진 + "PPG 천안 중식 3명"  ─▶  채팅방
채팅방  presign 요청 ─▶ Worker ─▶ PUT URL  ─▶  사진은 R2 로 직접 (앱 100MB 한도 안 탐)
채팅방  messages 쓰기 {text, fileUrl, uid, createdAt}
봇     onSnapshot 새 메시지 ─▶ /v1 작은 모델 구조화 ─▶ messages 쓰기 {type:'card', draft, skill}
봇     FCM 푸시 ─▶ 폰 ─▶ 방 열림 ─▶ 카드 표시 [확인 · 수정 · 반려]
직원   확인 ─▶ (시스템 시퀀스 03) t_workReports / t_expenses 기록
```

- **앱은 AI를 모른다.** Firestore에 쓰고 구독할 뿐이다. 봇이 방의 참여자로 답한다 → 앱 코드가 얇고, 스킬을 늘려도 앱은 안 바뀐다
- **AI가 먼저 묻는다**는 봇이 17:00에 방에 질문 메시지를 쓰고 푸시를 보내는 것 — 같은 경로
- 읽음 '1'은 기존 `channelReads`(방·사용자별 마지막 읽은 시각)로 계산 — 새 컬렉션 없음

## 3. 데이터 모델 — 기존 그대로 + 필드 몇 개

| 컬렉션 | 지금 | 추가 |
|---|---|---|
| `channels` | id · 이름 · 멤버 · DM/그룹 | `kind: 'dm' \| 'group' \| 'bot'` · `botId` |
| `messages` | `type` · `text` · `createdAt` · `fileUrl` · 보낸 이 | `type ∈ text \| image \| file \| card \| system` · `card{skill, draft{…}, status: draft\|confirmed\|rejected, confirmedBy, confirmedAt}` · `clientId`(중복 방지·오프라인 큐) |
| `channelReads` | 방_사용자 → 마지막 읽은 시각 | 그대로 |
| `users` | dept · position · role · grade | `fcm: [토큰…]` · `push: {quiet: '22:00-07:00'}` |

사진은 **Firestore에 base64를 넣지 않는다** — `fileUrl`만. 원본은 R2(A등급). B등급 방은 만들지 않는다(도면은 게이트, §설계서 2).

## 6. 만드는 순서 — 6주 (m3)

| 주 | 만들 것 | 파일 | 검증 (이게 되면 다음) |
|---|---|---|---|
| **W1** | PWA 껍데기 · 데이터 모델 확정 | `manifest.json` `sw.js` 최소 · 필드 추가 | 폰 홈 화면에 설치 · 비행기 모드에서 재열림 |
| **W2** | 채팅방 카톡식 · 사진 → R2 | `messenger.css` `messenger.js` · Worker `/presign` | 좌우 말풍선 · 읽음 '1' · 📷로 찍은 사진이 R2에, Firestore엔 URL만 |
| **W3** | FCM 푸시 · 봇 계정 | `sw.js` 푸시 · `users.fcm` · Worker `/push` · `messenger_bot.js` 구독 | **잠긴 폰에 푸시 → 누르면 그 방** · 봇이 방에 "받았어요" 답 |
| **W4** | 확인 카드 · 스킬 라우터 v0 | `shared/confirm-card.js` · 정규식 의도 분류 | 카드 확인 전 컬렉션 무변화 · 확인 후 1건 · 30문장 분류 |
| **W5** | 작업보고 스킬 | 17:00 잡 · `/v1/groq` 구조화 · `t_workReports` · 본인 합계 | 17:00 폰 울림 → 답 → 카드 → 확인 → 기록 (03 시퀀스 1회) |
| **W6** | TFT 8명 파일럿 2주 시작 | 집계 위젯 | 응답률 ≥ 80% · 건당 확인 ≤ 30초 (자동 집계) |

**순서의 이유**: 푸시(W3)가 봇보다 앞 — "AI가 먼저 묻는다"의 전제. 카드(W4)가 스킬(W5)보다 앞 — 확인 없이는 저장이 없다. 영수증 스킬은 W7~8(설계서 §9 P1-c).

## 7. 검증 장비와 조건

- 폰 3종: **iPhone(PWA · 웹푸시 iOS 16.4+)** · 안드로이드(PWA → P2에 TWA APK) · 데스크톱(플랫폼 iframe 안)
- 오프라인: 지하·현장에서 보낸 메시지가 `clientId`로 큐에 남고 복귀 시 한 번만 전송
- 푸시: 잠긴 화면 도달률 · 방해금지 시간(22~07시) 적용
- 읽음 '1': 두 폰으로 교차 확인
- 보안: `fileUrl`이 presigned가 아닌 공개 URL이면 실패 · 카드 확인은 본인 uid만
