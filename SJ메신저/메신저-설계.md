## 2. 작동 방식 (m2)

```
직원   사진 + "PPG 천안 중식 3명"  ─▶  채팅방
채팅방  presign 요청 ─▶ Worker ─▶ PUT URL  ─▶  사진은 R2 로 직접 (앱 100MB 한도 안 탐)
채팅방  messages 쓰기 {text, fileUrl, uid, createdAt}
봇     onSnapshot 새 메시지 ─▶ /v1 작은 모델 구조화 ─▶ messages 쓰기 {type:'card', draft, skill}
봇     FCM 푸시 ─▶ 폰 ─▶ 방 열림 ─▶ 카드 표시 [확인 · 수정 · 반려]
직원   확인 ─▶ (시스템 시퀀스 03) t_workReports / t_expenses 기록
```

- **앱은 AI를 모른다.** Firestore에 쓰고 구독할 뿐이다. 봇이 방의 참여자로 답한다 → 앱 코드가 얇고, 스킬을 늘려도 앱은 안 바뀐다
- **AI가 먼저 묻는다**는 봇이 17:00에 방에 질문 메시지를 쓰고 푸시를 보내는 것 — 같은 경로
- 읽음 '1'은 기존 `channelReads`(방·사용자별 마지막 읽은 시각)로 계산 — 새 컬렉션 없음

## 3. 데이터 모델 — 기존 그대로 + 필드 몇 개

| 컬렉션 | 지금 | 추가 |
|---|---|---|
| `channels` | id · 이름 · 멤버 · `type: announce\|dept\|project\|group\|dm` | **`kind` 는 안 만든다(W1 정정)** — `type` 이 이미 그 일을 하고 있었다. 봇 방은 `type:'bot'` + `botId` 로 (W3) |
| `messages` | `type` · `text` · `createdAt` · `fileUrl` · 보낸 이 | `type ∈ text \| image \| file \| card \| system` · `card{skill, draft{…}, status: draft\|confirmed\|rejected, confirmedBy, confirmedAt}` · `clientId`(중복 방지·오프라인 큐) |
| | | **W1 완료**: `type`·`clientId` 저장 시작. 문서 id = `msg_<clientId>` 라 같은 clientId 로 재시도하면 같은 문서를 덮어쓴다(두 번 안 찍힘). `card` 는 W4, `fcm` 은 W3 |
| `channelReads` | 방_사용자 → 마지막 읽은 시각 | 그대로 |
| `users` | dept · position · role · grade | `fcm: [토큰…]` · `push: {quiet: '22:00-07:00'}` |

사진은 **Firestore에 base64를 넣지 않는다** — `fileUrl`만. 원본은 R2(A등급). B등급 방은 만들지 않는다(도면은 게이트, §설계서 2).

## 6-1. W1 완료 기록 (2026-09-18)

**들어간 것** — `modules/messenger/` 에 `manifest.json` · `sw.js` · `icons/`(생성기 포함),
`messenger.html` 에 매니페스트·애플 메타·서비스워커 등록·독립실행 로그인 관문·`clientId`/`type` 저장,
`index.html` 에 로그인 후 되돌아가기 5줄(+ `MESSENGER_BUILD` b27→b28).

**설계에서 바꾼 것 셋**

1. **`channels.kind` 를 안 만들었다.** 실물 코드에 `type` 이 이미 `announce·dept·project·group·dm`
   다섯 값으로 쓰이고 있었다. 같은 일을 하는 필드를 하나 더 만들면 둘이 어긋난다. 봇 방은 `type:'bot'`.
2. **문서 id 를 `msg_<clientId>` 로 만들었다.** clientId 를 필드로만 두면 중복 방지에 조회가 한 번 더 든다.
   id 로 쓰면 같은 clientId 재전송이 같은 문서를 덮어쓴다 — W2 오프라인 큐가 그냥 안전해진다.
3. **manifest `scope` 를 `/` 로 뒀다.** 구글 OAuth 리디렉션 주소가 사이트 루트 하나만 등록돼 있어서
   로그인은 반드시 `/` 를 거친다. scope 가 `/modules/messenger/` 였으면 로그인하러 가는 순간
   앱 밖(브라우저)으로 튕긴다.

**고친 사고 하나** — `getCurrentUserUid()` 의 마지막 줄이 `return 'cwkim'` 이었다. 플랫폼 iframe 안에서는
부모가 항상 먼저 잡히니 티가 안 났지만, 홈 화면 앱으로 직접 열면 **로그인 안 한 사람이 전부 부장 계정으로
보였다.** 이제 모르면 `null` 을 돌려주고, 앱으로 열렸는데 로그인이 없으면 관문을 띄운다.
쓰기는 어차피 규칙(`author == request.auth.uid`)이 막고 있었지만 화면은 거짓말을 하고 있었다.

**검증** (`node test/pwa-w1.test.mjs` 31/31 · `node test/pwa-live-check.mjs` 13/13, 헤드리스 크롬)

| 본 것 | 결과 |
|---|---|
| 서비스워커 활성 · 껍데기+SDK 캐시 | 통과 (`sj-msg-v1`, 7개 + SDK 4개) |
| Firestore 롱폴링은 캐시 안 함 | 통과 (캐시하면 메시지가 멈춘다) |
| 비행기 모드 재열림 | 통과 (56,340바이트 렌더, 오류 없음) |
| 매니페스트 치명 오류 | 0건 · standalone + 192/512 |
| 앱으로 열면 관문 / iframe 안에서는 관문 없음 | 둘 다 통과 |

**아직 아닌 것** — ① 폰 실물 설치(안드로이드·iPhone)는 사람이 한 번 봐야 한다. ② 오프라인에서 열리긴 해도
**대화 내용은 안 보인다** — Firestore 로컬 캐시를 안 켰다. 오프라인 큐와 함께 W2.
③ 아이콘은 말풍선 도형이다. 로고를 쓰려면 `icons/make-icons.py` 를 고치고 다시 돌린다.

---

**순서의 이유**: 푸시(W3)가 봇보다 앞 — "AI가 먼저 묻는다"의 전제. 카드(W4)가 스킬(W5)보다 앞 — 확인 없이는 저장이 없다. 영수증 스킬은 W7~8(설계서 §9 P1-c).

## 7. 검증 장비와 조건

- 폰 3종: **iPhone(PWA · 웹푸시 iOS 16.4+)** · 안드로이드(PWA → P2에 TWA APK) · 데스크톱(플랫폼 iframe 안)

- 보안: `fileUrl`이 presigned가 아닌 공개 URL이면 실패 · 카드 확인은 본인 uid만
