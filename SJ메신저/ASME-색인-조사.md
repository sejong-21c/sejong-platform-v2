# ASME 코드북 색인 — 실측 조사 (2026-09-19)

부장님 요청: "ASME Code Book 전부 색인하면 기술부가 쓰기 좋겠는데. 안에 그림도 같이 나와야 한다."
아래는 **짐작이 아니라 파일을 직접 열어 확인한 것**이다. 다시 조사하지 말 것.

## 어디 있나
```
//Sjserver/10. iso 및 asme manual/2. ASME Manual/2. ASME 2023/5. Code Book
```
PDF 13권 · 약 145MB · **총 8,867쪽**. 전부 **텍스트 층이 살아 있고**(스캔본 아님) **암호도 없다**.
⚠️ 윈도우 UNC 경로는 도구에 따라 역슬래시가 먹히니 `//Sjserver/...` 슬래시 형태로 접근할 것.

## 두 갈래로 나눈다

조문·요건이 문장으로 되어 있어 깨끗하게 뽑힌다. 기술부가 실제로 찾는 것도 이쪽
("UT 적용 범위", "PQR 재시험 조건", "용접이음 효율").

### 표 중심 5권 — 그냥 넣으면 **위험하다** (II part A-1·A-2·B·C·D, 5,611쪽)
`Table 1A` 를 그대로 텍스트로 뽑으면 행 구조가 깨져 숫자만 세로로 늘어선다:
```
1 / 275 / 140 / NP / NP / 343 / NP / CS–6
```
여기서 `343` 은 **최고사용온도**지 허용응력이 아니고, 재료 규격명은 아예 이 쪽에 없다.
압력용기 회사에서 AI 가 이런 조각을 근거로 허용응력을 답하면 설계가 틀린다.

**해법 — Line No. 로 이어 붙인다.** Table 1A 는 세 쪽에 걸쳐 있고 `Line No.` 가 공통 열쇠다:
- 58쪽: Line No. + 재료 식별(조성·제품형태·**Spec. No.**·Type/Grade·P-No.)
- 59쪽: Line No. + 인장/항복강도 + 섹션별 최고온도 + 외압챠트번호
- 60쪽: Line No. + **온도별 허용응력 값**

세 쪽을 Line No. 로 join 하면 한 줄이 완성된다("SA-516 Gr.70 / 판재 / 인장 485 / 40°C 138 MPa").
조각 하나가 재료명부터 숫자까지 다 갖게 되므로 위험이 사라진다.
- `page.find_tables()` 는 **못 쓴다** — ASME 표는 괘선이 없어 1행 2열로 뭉개진다(확인함).
- 다행히 `page.get_text()` 가 **줄 순서를 지켜서** 뽑아 준다. 좌표까지 갈 필요 없다.
- ⚠️ **이어 붙인 결과를 쪽 이미지와 표본 대조해 눈으로 확인한 뒤에만** 올린다. 열이 하나 밀리면 전부 틀린다.
- 규격번호 대시는 하이픈이 아니라 **엔대시**(`SA–516`)다. `startswith("SA-")` 로 찾으면 0건 나온다.

## 그림 — 된다 (확인함)
- 그림은 페이지에 **삽입 이미지**로 박혀 있다(`page.get_images()`). 벡터가 아니다.
- 원본 해상도가 크다(예: Figure UG-28 이 6590×2971).
- ⚠️ `extract_image()` 로 꺼내면 **색이 반전**된다(1비트 마스크 때문). 그대로 쓰면 검은 바탕이 된다.
- **해법**: `page.get_pixmap(dpi=170, clip=박스)` 로 쪽에서 오려낸다. 캡션까지 같이 나오고 색도 정상이다.
  박스는 `page.get_image_bbox()` 들과 `page.search_for("Figure UG-28")` 을 합쳐서 잡는다.

## 저장·색인 한도 — **해결됨. 맥에서 한다(2026-09-19 오후)**
~~Vectorize 무료 4,880조각 한계 → Workers Paid $5/월 필요~~ → **낼 필요 없다.**
맥미니의 bge-m3(1024차원)로 색인·검색한다. **0원, 조각 수 상한 없음.**
- 색인 저장: `pais_project/data/doc-vec.bin`(Float32) + `doc-vec.json`(조각 본문·쪽)
- 검색: 파이스 `/api/rag/search` → 게이트웨이가 넘겨준다(v3.7). 맥이 꺼져 있으면 Vectorize 로 물러선다.
- **실측 속도: 1,826조각 색인에 92초** (≈20조각/초). 서술형 8권 약 1만 조각이면 8~9분.
- 게이트웨이 `/rag/upload`(Vectorize)는 여전히 문서당 500조각 상한이지만, 책은 그 길로 안 간다 —
  맥에서 `node scripts/doc-index-cli.mjs 조각.json` 으로 넣는다.
- 그림은 R2(`sejong-files`)에 넣고 `/file/sign` 으로 내준다. 그림 1,483장 ≈ 300MB (무료 10GB 안).

## 파이프라인 (완성, 2026-09-19)
```
세종플랫폼 PC:  node tools/pdf-to-chunks.mjs "책.pdf" --name "이름" --처음 51 --out 조각.json
        맥:    node scripts/doc-index-cli.mjs 조각.json
```
- `tools/pdf-pages.py` — PyMuPDF 로 쪽별 글자. **stdout 말고 파일로** 쓴다(윈도우 cp949 가 특수문자에서 죽는다).
- `tools/pdf-to-chunks.mjs` — 조각내기 + **쪽번호 되찾기**. 20자 미만 쪼가리는 버린다.
- 조각내기에 `{번호제목:false}` 를 준다 — ASME 표의 "75 (515)"·"18 UNF" 를 제목으로 오인해
  조각이 한 글자짜리로 부서졌다(처음 2,930조각·평균 271자 → 고친 뒤 1,826조각·평균 431자).
- 검사: `node test/pdf-to-chunks.test.mjs` · `node test/rag-chunk.test.mjs`

## Sec.IX 실측 결과 (첫 권, 2026-09-19)
373쪽 · 826,848자 → **조각 1,826개**(평균 431자, 쪽번호 100%) · 색인 92초.

→ 조각·색인은 정상. 포괄적인 한국어 질문은 AI 가 상위 5개를 보고 종합하므로 실사용에선 문제가 덜하다.

**중간에 잡은 함정**: 조각의 머리("… > QW-406 PREHEAT")를 메타로 저장만 하고 **벡터에는 본문만** 넣고 있었다.
제목에만 답이 있는 질문을 영영 못 찾는 상태였다. 지금은 "머리 + 본문" 을 함께 임베딩한다.
