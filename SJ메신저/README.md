## ⚠️ 상용 전에 **반드시** 할 것 — 방별 구독으로 전환 (2026 연말)

부장님 결정(2026-09-19): "일단 커튼 방식으로 해 놓고, 연말에 상용 전에 방별 구조로 바꾸자. 그거 꼭 해야 된다."

**지금(커튼)**: 연락처에는 내 부서만, 프로젝트 탭에는 내가 든 것만, 검색도 거기까지만 나온다.
화면으로는 남의 부서·프로젝트 방에 갈 길이 없다. 임원(super·exec)은 전부 본다.

**그런데 이건 잠금이 아니다.** 메신저는 아직 **모든 방의 최근 500건을 한 번에** 받아온다
(`messenger.js` 의 messages 구독, `index.html` 배지는 200건). 규칙도 `messages read: isCompanyUser()` 라
사내 로그인만 하면 전부 읽힌다. 즉 **남의 부서 대화가 모든 직원 브라우저 메모리에 내려와 있다.**
개발자 도구를 열 줄 아는 사람은 볼 수 있다. 70명에게 열기 전에 반드시 막아야 한다.

**왜 규칙만으로는 안 되나**: Firestore 는 목록 조회를 문서별로 걸러 주지 않는다. 한 문서라도 규칙에
걸리면 **조회 전체가 거부**된다. 지금처럼 전 방을 한 번에 받는 구조에서 읽기에 조건을 걸면 메신저가 아예 안 뜬다.

**전환 순서**(각 단계마다 되돌릴 수 있고, 통과 조건이 될 때만 다음으로)

| 단계 | 할 일 | 통과 조건 |
|---|---|---|
| 1 | `messenger.js` 를 **방별 구독**으로 (`where('channel','==',cid)` + `orderBy createdAt` + limit) | 화면이 지금과 똑같이 보인다 · ui-check 전부 통과 |
| 2 | `index.html` 안 읽은 배지도 같은 방식으로 | 배지 숫자가 지금과 같다 |
| 3 | 복합 색인(channel ASC + createdAt DESC) 만들고 규칙을 조인다 | 내 방은 읽히고 남의 부서 방은 permission-denied |
| 4 | 프로젝트 방·그룹 방도 같은 기준으로 | 참여자 아닌 방은 조회 거부 |

3단계에서 틀리면 **70명의 메신저가 한꺼번에 안 열린다.** 1·2 를 먼저 끝내고 화면이 멀쩡한 걸 본 뒤에 규칙을 건드린다.
규칙에서 방 멤버를 확인할 때 문서마다 `get()` 을 부르면 안 된다(질의당 접근 20회 제한). 방별 조회는
`channel` 이 고정이라 같은 경로 `get()` 한 번으로 끝난다 — 그래서 방별 구독이 전제다.
덤으로 500건 창 문제(오래된 방의 옛 대화가 안 보이는 것)도 같이 풀린다. W2-b 의 "방별 페이지네이션"이 바로 이 일이다.
