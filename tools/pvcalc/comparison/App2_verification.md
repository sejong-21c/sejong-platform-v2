### 1. Table 2-7.1 (F, V, f) 37개 상수 체인 ✅

App. 2는 직선 허브(g1 = g0, 즉 A = 0)에서 **F = 0.908920, V = 0.550103**을
줍니다. 이 공표값이 체인 전체의 외부 검증 앵커입니다.

| h/h0 | C = 43.68(h/h0)⁴ | 계산된 F | 계산된 V |
|---|---|---|---|
| 0.183 | 0.049 | **0.908920** | **0.550103** |
| 0.456 | 1.896 | 0.908916 | 0.550097 |
| 1.10 | 62.9 | 0.908720 | 0.549669 |
| 2.74 | 2457 | 0.906391 | 0.538959 |

작은 C에서 **6자리까지 정확히 일치**합니다. C가 커질수록 미세하게 흐르는데,
이는 A = 0에서도 살아남는 `1/C` 항 때문이므로 수식 자체의 거동입니다
(공표값은 h/h0 → 0 극한값). 실제 허브 비율에서 0.02% 이내이고, F·V는
`e = F/h0`, `d = (U/V)·h0·g0²`를 거쳐 L에 들어가므로 응력 영향은 그보다 작습니다.

`tests/run_tests.py`가 이 앵커를 1e-5 상대오차로 고정하고, 긴 허브에서도
0.5% 이내임을 확인합니다.

### 2. 참고 구현(thepvguy/calctoys)에서 발견한 오타 2건

`reference/calctoys/src/Flange/common/Div1Common.py`의 Table 2-7.1 구현에
전사 오류가 있습니다. **pvcalc는 고쳐서 구현했습니다.**

| 위치 | 원본 | 수정 |
|---|---|---|
| `C_21` 3번째 항 | `C_3 * C_4 * C_2` | `C_3 * C_14 * C_2` |
| `C_24` 감산항 | `C_3 * C_7 * C_6` | `C_3 * C_7 * C_5` |

근거: C_20/C_21/C_22는 각각 C_9·C_13 / C_10·C_14 / C_11·C_15 행을 쓰고,
C_23/C_24/C_25는 각각 C_4 / C_5 / C_6을 씁니다. 두 곳만 이 패턴에서 벗어납니다.
그리고 **두 곳을 모두 고쳐야만** F·V가 위 표처럼 앵커값에 수렴합니다.
원본대로면 C=200에서 F=15.96, V=−3.49로 발산합니다.

추가로 원본의 `F`는 부호가 반대입니다 (`E_6/den` → `-E_6/den`). 원본은
`g_1 == g_o`일 때 `return 0.908920`으로 하드코딩해 이 지점만 가려두고 있습니다.

### 4. 허브 있는 루즈형 플랜지 (F_L, V_L) — **미구현**

Table 2-7.1의 F_L·V_L은 A → 0에서 C에 무관하게 수렴하지 **않습니다**:

| C | 계산된 F_L | 계산된 V_L |
|---|---|---|
| 5.0 | −1.3296 | 0.9691 |
| 43.68 | −0.9292 | 0.5688 |
| 200 | −0.8966 | 0.5579 |

F와 달리 앵커로 판정할 수 없어 부호·수식을 확정하지 못했고, 추측 대신
**루즈형+허브 조합을 아예 제외**했습니다 (`flange_type`은 `integral` /
`ring`만 허용).

→ **확인 요청**: Table 2-7.1의 F_L·V_L 식. 특히
- `F_L = [C18(0.5+A/6) + C21(0.25+11A/84) + C24(1/70+A/105) − (1/40+A/72)] / den_F` 이 맞습니까?
- `V_L = [0.25 − 0.2·C24 − 1.5·C21 − C18] / den_V` 이 맞습니까?
- 부호 규약은? (F와 같이 음수를 뒤집어야 하는지)
- Fig. 2-7.5/2-7.6에서 g1/g0 = 1일 때 F_L·V_L 값이 h/h0에 따라 변합니까?
  변한다면 위 C 의존성은 정상이고 부호만 확인하면 됩니다.

### 5. Table 2-6 하중 팔길이 — 스케치 범위

현재 두 계열로만 구현했습니다.

```
인테그럴 (Fig. 2-4 스케치 1~4c):
  R  = 0.5(C − B) − g1
  hD = R + 0.5·g1
  hT = 0.5(R + g1 + hG)
루즈 (스케치 5~7):
  hD = 0.5(C − B)
  hT = 0.5(hD + hG)
공통:
  hG = 0.5(C − G)
```

→ **확인 요청**: 스케치별로 위 두 계열에서 벗어나는 예외가 있습니까?
(특히 루즈형 중 랩조인트 계열, 그리고 옵셔널형 스케치 8~12a)

### 6. App. 2-5(c) 유효 개스킷 폭 b

현재 Table 2-5.2 스케치 구분 없이 다음만 구현했습니다.

```
N   = (개스킷 접촉면 OD − ID)/2
b_o = N/2
b_o ≤ 6.35mm (0.25in) → b = b_o,        G = 접촉면 평균지름
b_o > 6.35mm         → b = 2.52√b_o [mm] (0.5√b_o [in]),  G = OD − 2b
```

→ **확인 요청**: `b_o = N/2`는 Table 2-5.2 스케치 1a/1b(평면·라이즈드 페이스)
기준입니다. 실무에서 쓰는 다른 페이싱(스케치 1c~6)에서 `b_o`가 달라지는
경우가 있으면 알려주십시오. 그루브·재킷 개스킷 쓰실 일이 있으면 필요합니다.
