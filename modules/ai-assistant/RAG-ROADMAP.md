# RAG 문서고 로드맵 — `feature/rag-docs` 브랜치

작성: 2026-07-28 · 기반: 로드맵 8단계 MVP (워커 v3.2.2, ai-assistant.js v29.62)

**목표**: "절차서 붙여넣기" 수준의 MVP를 → **ASME 코드북급 사내 기술 문서고**로.
"ASME Sec VIII에서 외압 계산 기준 말해줘" → 올려둔 코드북에서 해당 조항을 찾아
**출처(문서명·페이지)와 함께** 답하는 것이 완성 그림. 나아가 검증된 수식 모듈과
연계해 "근거 조항 + 개산"이 한 대화에서 나오게 한다.

**작업 규칙**: 이 브랜치에서 개발 → 단계 완성마다 main으로 merge (main 직push 금지,
force push 절대 금지). 한 단계 = 독립 배포 가능.

## 현황 (main에 이미 배포된 것)

- 워커 /rag/upload·/rag/search (Vectorize `sejong-docs` 1024·cosine + Workers AI bge-m3)
- 🔑 모달 관리자 등록 UI — 텍스트 붙여넣기, 문서당 500조각(≈300쪽) 제한
- search_docs 도구 — 출처는 문서명까지만 (페이지 없음)
- 제약: 스캔본(이미지 PDF) 미지원, Vectorize 무료 한도 ≈ 총 1,000쪽 분량

## R1 — PDF 업로드 (난이도: 중)

**목표**: 텍스트 복사·붙여넣기 대신 PDF 파일을 그대로 올린다.

- 🔑 등록 섹션에 파일 선택 추가 — pdf.js(CDN lazy 로드)로 **브라우저에서** 텍스트 추출
  (워커 CPU 한도 회피 — 추출·분할은 전부 클라이언트, 워커는 임베딩·저장만)
- 페이지별 텍스트를 유지한 채 추출 (R3의 페이지 출처를 위해 조각에 page 번호를 심는다)
- 추출 결과 미리보기(글자 수·페이지 수) 후 등록 — 텍스트가 안 나오는 스캔본은
  "이미지 PDF는 지원하지 않습니다" 안내
- 진행률 표시 (N/M 페이지 추출 → K조각 등록 중)

**완료 기준**: 텍스트 PDF 1권 업로드 → 등록 완료 → 내용 질문 정답.

## R2 — 대용량 분할 등록 (난이도: 중)

**목표**: 문서당 500조각(≈300쪽) 제한 해제 — 수천 쪽도 한 번에.

- 클라이언트가 조각을 파트(500개 단위)로 나눠 /rag/upload 연속 호출
  — 조각 id는 `문서명::전역번호` 유지, 파트별 실패 시 해당 파트만 재시도
- 워커: replace(재등록) 시 삭제 범위를 500 고정이 아니라 문서 대장(R4)의 기존
  조각 수 기준으로 — 대장 도입 전까지는 파트 업로드 시 `replace=false` 파라미터로 이어붙이기
- 등록 중 이탈 대비: 마지막 완료 파트를 localStorage가 아닌 **문서 대장에 기록** (이어올리기)

**완료 기준**: 1,000쪽급 PDF 등록 완주 + 중간 끊고 이어올리기 성공.

## R3 — 페이지 출처 표시 (난이도: 하)

**목표**: 답변 출처가 "검사절차서"가 아니라 "검사절차서 p.45".

- 조각 메타데이터에 `page`(시작 페이지) 저장 — R1의 페이지별 추출과 연동
- /rag/search 응답과 search_docs 반환에 page 포함
- 시스템 프롬프트: 출처 표기를 "문서명 p.N" 형식으로 명시

**완료 기준**: 질문 3종의 답변 출처에 페이지 표시, 원본 대조 일치.

## R4 — 문서 대장 (난이도: 중)

**목표**: 뭐가 등록돼 있는지 보고, 지울 수 있게.

- Firestore `t_aiDocs/{문서명}`: 조각 수·페이지 수·등록자·등록일시·파트 진행 상태
  (t_* 와일드카드 규칙이라 firestore.rules 변경 불필요 — 확인됨)
- 워커 /rag/delete {docName}: 대장의 조각 수만큼 id 삭제 + 대장 문서 삭제 (관리자만)
- 🔑 등록 섹션에 등록 문서 목록 + 삭제 버튼, AI에게 "등록된 문서 뭐 있어?"도 조회 가능(query_state에 aiDocs 추가)

**완료 기준**: 등록→목록 표시→삭제→검색에서 사라짐 확인.

## R5 — 검색 품질 튜닝 (난이도: 중)

**목표**: 코드북처럼 밀도 높은 문서에서 정답 조각이 상위에 오게.

- topK 5→8 + 스코어 하한선(관련 없으면 "못 찾음"이라 답하게)
- 인접 조각 이어붙이기 — 검색된 조각의 앞뒤 조각(같은 문서 연속 번호)을 함께 반환해 문맥 제공
- 질의 재작성: 모델이 검색 전에 질문을 검색용 키워드로 정리하도록 시스템 프롬프트 보강
- (선택) 조각 겹침 100→150자, 표 많은 구간 분할 규칙 개선

**완료 기준**: 준비한 질문 10개 중 8개 이상에서 정답 조각이 근거로 사용됨.

## R6 — 코드북 전권 등록 (⏸ Workers Paid 결제 후)

- Workers Paid($5/월) 전환 → Vectorize 저장 한도 해제 (코드북 수십 권도 월 수백 원 수준)
- ASME Sec VIII·Sec II-D·TEMA 등 실제 등록 + 사용량(임베딩·쿼리) 모니터링
- 같은 결제로 R2도 열림 → 보류 중인 Firestore 야간 백업(BACKUP 바인딩)도 이때 활성화
  (gateway/wrangler.toml 주석 해제 + `wrangler r2 bucket create sejong-backup` + deploy)

## R7 — 강도 개산 계산기 연동 (후속, 별도 검토)

- 원칙: **AI가 계산하지 않는다** — 검증된 수식 모듈(코드)이 계산, AI는 입력 통역·결과 해설
- 1차: UG-27 내압 두께·MAWP 역산 + 사용 재료 위주 Sec II-D 허용응력 테이블
- 결과에 "개산용 — 정식 계산은 검증된 SW" 명시, 수식마다 상용 SW 대조 검증 케이스
- RAG와 연계: 답변에 근거 조항(R3 페이지 출처) + 개산 결과를 함께

## 공통 원칙

1. 등록·삭제는 관리자(RAG_ADMIN_EMAILS)만, 검색은 사내 로그인 전체 — 저작권 자료는 사내 범위 유지
2. 무거운 일(추출·분할)은 브라우저, 워커는 임베딩·저장만 (CPU 10ms 한도)
3. 스캔본 PDF 미지원을 UI에 명시 — 조용한 실패 금지
4. 검증: 실제 PDF로 등록→질문→출처 대조까지. 워커 변경은 `node gateway/worker-test.mjs` 통과 필수
