# AI 비서 기능 확대 로드맵

작성: 2026-07-26 · 기준 구현: ai-assistant.js v29.45 (플랫폼 v30.10)

한 세션에 한 단계씩 완성한다. 각 단계는 독립적으로 배포 가능해야 하고,
완료 기준(검증)을 통과해야 다음 단계로 넘어간다.
검증 원칙: 코드 수정 후 반드시 **새로고침 → 로그인 → 실제 질문**까지 확인한다.

## 1단계 — 조회 범위 확대 (난이도: 하)

**목표**: "이번 달 NCR 몇 건이야?" 같은 질문에 답할 수 있게 한다.

- `QUERYABLE`에 분리 모듈 컬렉션 추가: `ncrs`, `cars`, `measurementTools`,
  `measurementCheckouts`, `meetingReservations`, `meetingMinutes`, `wbsRec`
- 분리 모듈 데이터는 부모 `state`에 없으므로 `queryState()`에서 Firestore를
  직접 1회 조회(getDocs)하는 분기 필요 — 상시 구독은 하지 않는다(비용).
- 시스템 프롬프트의 "NCR/CAR 미지원" 문구에서 **조회** 부분 해제 (등록은 여전히 미지원 명시)
- 조회 결과에도 사용자 ID → 이름 치환(`resolveUserIds`) 적용

**완료 기준**: NCR·CAR·측정기구·회의실 각각 1개 질문에 실데이터로 답변.

## 2단계 — 화면 이동 액션 (난이도: 하)

**목표**: "NCR 모듈 열어줘" → 해당 화면으로 바로 이동.

- `open_module` 액션 1개 등록 — 파라미터: 모듈명(한글 별칭 허용)
- 기존 네비게이션 함수(사이드바 메뉴 전환) 재사용, 모듈명 → 메뉴 매핑 테이블
- 존재하지 않는 모듈명이면 가능한 목록을 답변으로 안내

**완료 기준**: "결재 열어줘", "WBS 보여줘" 등 5개 모듈 이동 확인.

## 3단계 — 대화 기록 유지 (난이도: 하~중)

**목표**: 새로고침해도 대화가 이어진다.

- `history` 배열을 localStorage에 저장/복원 (사용자별 키, 최근 N턴 제한)
- 패널 열 때 이전 대화 복원 렌더 + "새 대화" 버튼 추가
- 주의: 대화에 조회 데이터(function result)가 포함되므로 용량 제한 필수
  (결과 턴은 요약 저장 또는 제외). localStorage는 **기록 저장에만** 쓴다
  — 중복 방지 게이트로는 금지(2026-07-17 WBS 사고 교훈).

**완료 기준**: 질문 → 새로고침 → 로그인 → 패널에 이전 대화 표시 + 이어서 질문 성공.

## 4단계 — 분리 모듈 등록 연동 (난이도: 중)

**목표**: "어제 발견한 용접 불량 NCR로 올려줘" → NCR 모듈이 열리고 폼이 채워진 상태.

- 방식: 모듈 URL 파라미터(`?aiPrefill=<json>`) 또는 postMessage로 프리필 전달
- 각 모듈(ncr.html, car.html)에 프리필 수신 코드 추가 — 수신 시 등록 폼 자동 오픈+채움
- 저장은 지금처럼 사람이 확인 버튼 — AI 직접 저장 금지 원칙 유지
- 대상: NCR → CAR 순서로. 성공하면 측정기구 반출 등으로 확대

**완료 기준**: AI 요청 → NCR 등록 폼 프리필 확인 → 사람이 저장 → 목록 반영.

## 5단계 — 브리핑 기능 (난이도: 중)

**목표**: "오늘 뭐 해야 해?" 한 마디로 내 업무+일정+결재 대기+마감 임박 요약.

- `get_briefing` 도구 1개: 현재 사용자 기준으로 tasks(내 담당+마감 임박),
  events(오늘/이번 주), approvals(내 차례 + 전결 가능), 미읽음 메시지 수를 묶어 반환
- 서버 호출 없이 이미 구독 중인 state에서 조립 — 빠르고 무료
- 패널 첫 오픈 시 "오늘 브리핑 보기" 추천 버튼 노출

**완료 기준**: 실사용 계정으로 브리핑 질문 → 4개 영역 모두 실데이터 요약.

## 6단계 — 교차 분석 질문 (난이도: 중)

**목표**: "이번 분기 프로젝트별 NCR 발생 현황 요약해줘" 같은 복합 질문.

- `query_state`에 필터 파라미터 추가(기간, 프로젝트, 담당자, 상태) — 원본을
  통째로 넘기지 말고 서버(클라이언트)에서 걸러서 토큰 절약
- 여러 컬렉션 연속 조회(최대 5회 루프는 기존 구조 그대로) 시나리오 점검
- 큰 컬렉션(200건 초과 truncate)은 필터 적용 후 재판단

**완료 기준**: 기간+프로젝트 조건이 함께 걸린 질문 3종 정답 확인.

## 7단계 — 문서 생성 PDF/Excel (난이도: 중~상)

**목표**: "이 결과 엑셀로 뽑아줘" → 조회 결과를 파일로 다운로드.

- WBS 모듈의 기존 PDF/Excel 출력 코드(jsPDF·SheetJS 등) 재사용
- `export_result` 액션: 직전 조회 결과(표 형태)를 Excel/PDF로 변환해 다운로드
- 한글 폰트 임베드 여부 확인 (WBS 출력에서 이미 해결했으면 그대로)

**완료 기준**: 조회 → "엑셀로" → 파일 다운로드 → 열어서 데이터 확인.

## 8단계 — 사내 문서 검색 RAG (난이도: 상)

**목표**: "용접 검사 기준이 뭐야?" → 품질 매뉴얼·절차서 근거로 답변.

- 게이트웨이(Cloudflare Worker) 확장: 문서 임베딩 저장(Vectorize 또는 D1) + 검색 API
- 문서 등록 파이프라인: PDF/한글 문서 → 텍스트 추출 → 청크 → 임베딩 (관리자 도구)
- `search_docs` 도구 추가, 답변에 출처(문서명·페이지) 표시
- 선행 조건: 게이트웨이 운영 경험 축적(1~7단계 동안 사용량·오류 관찰)

**완료 기준**: 절차서 1권 등록 → 내용 질문 3종 → 출처 포함 정답.

## 9단계 — 능동 알림 (난이도: 상)

**목표**: 마감 임박·결재 지연을 AI가 먼저 메신저로 알려준다.

- 게이트웨이에 Cron Trigger 추가(Cloudflare Workers 스케줄러)
- 서버에서 Firestore 조회(Admin 자격) → 조건 충족 시 messages 컬렉션에 알림 기록
- 알림 규칙은 소수로 시작: ① 마감 D-1 업무 ② 3일 이상 대기 결재
- 중복 알림 방지는 Firestore 마커 문서로(localStorage 금지)

**완료 기준**: 테스트 데이터로 두 규칙 모두 발화 확인 + 중복 발송 없음 확인.

---

## 원칙 (전 단계 공통)

1. **AI는 직접 저장하지 않는다** — 폼 프리필 + 사람 확인. 예외는 확인 카드(전송 버튼) 방식만.
2. **한 단계 = 한 커밋(또는 소수 커밋) = 독립 배포 가능** — 중간에 멈춰도 서비스는 정상.
3. **검증은 새로고침 → 로그인 → 실질문까지** — 콘솔 무오류만으로 완료 처리 금지.
4. **무료 한도 우선** — 게이트웨이·키 체인 구조를 해치는 변경 금지, 토큰 절약(필터·truncate) 우선.
5. firestore.rules 변경이 필요한 단계(1, 9)는 **저장소와 콘솔 양쪽 동시 갱신**.
